TITLE: 星際大戰：銀河來的客服
STYLE: 《星際大戰》續集式外傳 · 字卡開場的太空冒險，囉嗦禮儀機器人與嗶嗶叫的搭檔
NOTE: 本篇為《星際大戰》（1977）的同人外傳式改編，沿用原片機器人 C-3PO 與 R2-D2、塔圖因的莫斯艾斯利太空港、酒館拒絕機器人入內、R2 藏著全息訊息、片尾頒勳典禮等設定；貿易公會總管薇拉·索恩、老商人歐德、公會的帳務機器人 K-7 為新角色。理財顧問 Wendy 為原文中的情境人物，電商退換貨 AI 客服 Agent 的導入經驗為原文作者團隊親身見證，劇中都以 R2 帶來的全息紀錄呈現，非角色經歷。
## 前情提要
> 原片裡，R2-D2 帶著一段藏起來的全息訊息穿越沙漠，C-3PO 一路抱怨，兩台機器人最後幫反抗軍贏得勝利；頒勳典禮上，英雄們站上台，機器人站在旁邊。本篇設定在多年後的塔圖因：戰爭結束，莫斯艾斯利成了繁忙的貿易港，貿易公會開始讓機器人代理替客人處理交易。R2 又帶來了一段訊息，這次來自一顆遙遠的藍色行星。
## 字卡｜很久以前
> 很久以前，在一個遙遠的星系……
> 二十年來，銀河裡所有關於「體驗」的星圖，都只畫著一種旅人：會看、會感覺、會點按鈕的生命體。
> 如今，一種新的乘客登上了艦橋。它沒有眼睛，沒有情緒，卻握有決策的權力。大多數艦隊，還沒有替它準備座位。
## 第一章｜R2 藏著的訊息
~ 莫斯艾斯利，貿易公會的帳房。雙太陽已經落下，燈只亮了一半。帳務機器人 K-7 的燈號一明一暗，安靜地吐出一張又一張報表。
總管薇拉·索恩沒有看報表。她把報表推到一旁，親手翻開舊帳本，一筆一筆核對。
「她今天第四次這樣做了。」C-3PO 小聲對 R2 說，「真令人難過。K-7 明明幾秒就能算完。」
R2 嗶了一聲，頭頂的投影鏡亮起，在桌面上投出一段藍色的全息影像。
「R2 說，這是他從一顆叫地球的行星檔案庫裡帶回來的。」C-3PO 翻譯，「那裡的人，也遇過一模一樣的事。」
影像裡是晚上八點的財富管理辦公室。理財顧問 Wendy 盯著螢幕，游標停在「重新產生摘要」的按鈕上。這是她當天第四次，把 AI Agent 剛吐出來的客戶資產配置報告，重新拉開 Excel 手動核對。那套 Agent 技術不差，幾秒就能彙整客戶的股票、基金、保單配置，理論上該省下她大半天。可是上線三個月，使用率遠低於預期，顧問們寧可自己查，也不敢把 Agent 的輸出直接拿去見客戶。
「為什麼？」薇拉問。
R2 又嗶了幾聲。「他說，那個 Agent 做事時從不告訴人它在做什麼。」C-3PO 停了一下，「有沒有存取到最新資料、有沒有漏掉某個帳戶、看到的是不是舊版本。說真的，R2，你自己也常常這樣。」
R2 發出一聲很不服氣的口哨。
薇拉看向 K-7。它也是這樣：悶著頭做事，從不回報進度。動作再快，也沒有人敢把重要的事交給它。
「問題不在它算得快不快。」她慢慢說，「是它從來沒有被設計成一個值得信任的工作夥伴。」
> 地球人管這個叫 Agent Experience，AX。
它牽動的不只是薇拉和 Wendy 這樣的內部人員，還有每一個正在把決定交給機器的客人。
## 第二章｜只畫一種旅人的星圖
~ C-3PO 調出地球檔案庫的體驗設計紀錄，一張接一張。「天哪，」他說，「他們的會議二十年來都長得一模一樣。」
行銷主管打開報告：App 的流失漏斗、官網熱圖、會員旅程的掉落點。討論的焦點，永遠是那個拿著手機、坐在電腦前的消費者。從 1990 年代 Donald Norman 在蘋果確立概念，到 Nielsen Norman Group 系統化成方法論，這門學科從沒被正面質疑過：體驗的主體是誰？答案只有一個，真實的人類消費者。
「後來有人把星圖畫大了一點。」C-3PO 繼續翻。Gartner 在 2022 年提出 Total Experience（TX）框架，第一次系統性擴展「體驗主體」：顧客體驗（CX）、使用者體驗（UX）與員工體驗（EX），不是三條平行航道，而是互相牽連的生態系。員工能不能快速拿到正確資訊，直接決定顧客在通訊另一頭感受到的服務品質。
Gartner 預測，到 2026 年，全球六成大型企業將仰賴 TX 策略轉型商業模式。Forrester 的研究印證了代價：
NUM: 2.3–3.8%｜高品質員工體驗企業，年均股票回報高於同業的幅度
薇拉若有所思。體驗設計從來不只是在設計客人看到的那個畫面。在 TX 的時代，它同時涉及消費者的 UX、員工的 EX，以及高階主管的決策體驗（Decision Experience）。
「可是三種加起來，」C-3PO 說，「還是只有一種主體：人類。」
R2 轉了一圈，嗶了一聲。
「是的，R2。直到我們這種東西進場。」
## 第三章｜第三種體驗
~ 全息影像換了一頁。標註的日期，是地球曆 2025 年 1 月。
雲端託管大廠 Netlify 的執行長 Mathias Biilmann 提出一個概念，邏輯很簡單：已經有 UX 讓使用者有好體驗，也有 DX（Developer Experience）讓開發者有清楚的文件；當 AI Agent 成為使用產品的主體之一，就需要第三個概念，讓 Agent 在互動時也有順暢、可預測、可信賴的體驗。
麥肯錫 2025 年的報告畫出了規模：88% 的受訪企業已在至少一項商業功能中定期使用 AI，但只有約三分之一開始規模化。
「一扇窗正在打開。」薇拉說，「現在做的設計決定，會變成往後十年的標準。」
不管是公會裡替她記帳的 K-7，還是將來在港口替客人辦事的服務機器人，基準線都會從現在開始畫。
## 第四章｜跳進超空間的航線
~ R2 投出一張航線圖。舊航線彎彎曲曲，停靠十幾個站；新航線只剩短短一截，像一次超空間跳躍。
過去，客人的體驗建立在「人主動操作」上：有需求就搜尋，看到廣告就點擊，遇到問題就問櫃台。系統在客人發出明確訊號後才回應，這是指令回應式體驗（Request-Based Experience）。Agent 把它推向代理協作式體驗（Agent-Assisted Experience）：理解目標、判斷情境、整理選項，在授權範圍內協助完成任務。
「所以它不是比較聰明的問答機器人？」薇拉問。
「問答機器人解決的是回答的效率。」C-3PO 挺直身子，「Agent 改變的是任務本身怎麼被執行。」
就像訂一趟旅程。過去要一一比較航班、旅店、評價、保險，再付款排行程，資訊負擔又長又重。在 Agent Experience 裡，客人只要說出預算、日期與偏好，Agent 就先整理出幾套可執行的方案，大量的搜尋與比較成本被 AI 吸收。
> 顧客旅程壓縮（Journey Compression）。
「停靠站變少了，」薇拉說，「每一站就更重要。」
接觸點變少，不代表品牌影響力不重要；每一次被 Agent 選中、推薦、呈現的機會，都更關鍵。當 Agent 只給客人看三個選項而不是三十個，品牌怎麼被理解、被排序、被信任，就是新戰場。
介面也在變形。過去首頁怎麼排、表單有哪些欄位，都由企業預先設計；現在介面因人、因情境、因任務而變：同一個金融服務，對新客戶呈現簡化的方案比較，對既有會員直接顯示資產狀況與到期提醒。生成式使用者介面（Generative UI）的商業意義，是介面從固定流程，變成動態的服務入口。
理解客人的方式也在變。除了搜尋關鍵字、瀏覽商品、加入購物車這些主動表達，AI 還讀得出沒說出口的訊號：反覆查看某類商品、購買週期接近、在流程中停留過久。競爭從需求捕捉（Demand Capture）轉向需求預測（Demand Anticipation），在客人開口之前就先理解他的狀態。
C-3PO 舉起一隻手指：「不過，同一種預測能力，可以拿來更早打擾客人，也可以讓 Agent 懂得節制：知道何時提醒、何時協助、何時沉默。」
傳統的行銷自動化追求觸發與轉換；Agent Experience 必須同時理解情境、任務、風險，和人的感受。
## 第五章｜退貨櫃台的三重難題
~ 隔天，公會的服務機器人正式在港口上線。C-3PO 試著用對待人類的方式和它溝通：鞠躬、放慢語速、把顯示板調得更好看。毫無反應。「我有不好的預感。」
它沒有情緒，不會因為畫面好看而多停留。但通訊不穩，它就中斷任務；指令不夠明確，它在幾十個步驟之後就偏離了初衷。設計人類體驗靠的是同理心，感受使用者的情緒與挫折；這套訓練，對設計 Agent 的體驗幾乎沒有直接用途。
R2 調出地球的 Nielsen Norman Group 2026 年 State of UX 報告：2026 年，信任將是 AI 體驗最核心的設計問題，而且越來越多 Agent 在還沒準備好時就被推出，挑戰只會加劇。
信任有兩層。設計層，AI 新創公司 Pixelmojo 歸納出六個 AX 核心信任模式：
> 意圖預覽 · 自主性調節 · 信心訊號 · 可解釋推理 · 行動稽核 · 升級路徑
治理層，薇拉在帳房牆上寫下三個問題：AI 知道我什麼？AI 可以替我做什麼？AI 做錯了誰負責？低風險的任務可以高度自動化，例如查詢訂單、安排提醒；高風險的任務需要明確確認與人工支援，例如金融交易、醫療建議、保險申請。
「客人不授權，」她說，「功能再多的 Agent 也動不了。」最成功的公會，會是最能讓客人放心授權的公會。信任是 Agent Experience 能不能運作的基礎設施。
~ R2 又投出一段影像，標註：原文作者團隊，親身見證。
那是地球上一個電商客戶的退換貨 AI 客服 Agent，初版設計裡沒有清楚的升級路徑。一位顧客同時遇上三個問題：商品瑕疵、超過鑑賞期兩天、又碰上跨境退貨的物流特例。Agent 沒有停下來，先引用一般政策，發現不適用又改口引用瑕疵品條款，兩次回覆前後矛盾。顧客打出一行字：「所以到底可以退還是不可以」，語氣已經明顯不耐。
後來團隊加了一道門檻：只要案例涉及兩項以上政策的交叉判斷，Agent 就主動停下，回覆「這個問題我想讓同仁協助您確認」，並把三個衝突點整理成摘要，即時轉接。改版之後，這類複雜案例的顧客滿意度不再斷崖式下滑；客服團隊也開始主動查看 Agent 轉來的案例，而不是想從頭再問一次。
「你看，R2，」C-3PO 說，「知道自己什麼時候該閉嘴、去找人類，是一種美德。」
> Agent 的限制是設計出來的，不是缺陷。不知道自己邊界在哪裡的 Agent，比清楚知道何時該停下來的，危險得多。
## 第六章｜老商人的質疑
~ 港口的老商人歐德聽完，嗤了一聲：「說穿了，就是舊規矩換個名字。讓人看得到系統在幹嘛，地球人幾十年前就寫過了。」
這值得誠實面對。意圖預覽、可解釋推理，拆開來看，很像可用性工程裡「系統狀態可見性」的變體，Jakob Nielsen 在 1990 年代就寫過類似的守則。
R2 把兩段全息影像並排播放：Wendy 的深夜核對，和那位問「到底可以退還是不可以」的顧客。
「舊規矩失敗的時候，是人看不懂畫面。」薇拉說，「新的失敗，是另一套系統沒有能力表達自己的狀態。Agent 不是看不懂按鈕，它根本沒有按鈕可以看。」
當互動的一方從人類換成沒有視覺、沒有情緒，卻有決策權的軟體，好看、直覺、令人愉悅這些詞幾乎全部失效，得換成穩定性、可驗證性、可追溯性。這不是換皮，是換了整套評分表。
歐德沒再說話。這個問題不會在今天有最終答案。標準未定，是這個階段最真實的樣子；也正因為未定，現在的設計決定，才會變成將來的基準線。
## 第七章｜四道艙門
~ 公會的舊貨艙裡，有四道生鏽的艙門。薇拉決定一道一道打開。
第一道，從設計介面，到設計工作條件。對 Agent 來說，介面幾乎不存在；它的工作條件是另一套語言：任務指令的精確度、資料存取的邊界、出錯時的回饋機制。麥肯錫的報告點出，Agentic AI 早期的成功案例，共同點不是挑了最聰明的模型，而是挑了最清晰的工作流程。
第二道，從單一使用者，到多主體協同。協同不只發生在多個 Agent 之間，也發生在客人與員工之間，兩者是同一件事的兩面。員工得在好幾套系統間查資料、複製貼上、確認流程狀態，客人就感受不到即時又一致的服務；內部 Agent 能幫員工快速理解客人背景、查詢服務紀錄，外面的體驗才會順。這不是前台多一個 AI 入口，而是整個作業系統的治理問題：前台再聰明，後台資料分散、流程斷裂、員工接不了手，客人感受到的仍是不連貫。
第三道，從優化單次會話，到設計持續關係。Agent 把今天學到的記住，明天更有用。設計者得思考記憶架構：該記住什麼、記多久、什麼時候記憶反而帶來偏誤而需要重置。
第四道，從以人為中心，到以信任為中心。「以使用者為中心」沒有過期，但使用者不再只有人類。對人，信任靠一致的視覺語言建立；對 Agent，信任靠穩定的 API 回應與可驗證的資料格式。地球的世界經濟論壇在 2026 年的分析說了同樣的道理：要讓人信任一套 AI 的作為，得先讓人看懂它知道什麼、被允許做什麼、實際做了什麼。
「這是人類體驗設計的終點，」C-3PO 說，「也是我們這種的起點。」
## 第八章｜被選中的那一艘
~ 港口停著三十艘貨船。一位客人的 Agent 只挑了三艘給他看。公會的船，不在裡面。
過去，品牌爭的是注意力：誰被看見、被點擊、被記住，誰就進得了考慮名單，於是大家投資廣告、內容、搜尋排名、會員經營。未來仍需要注意力，但還需要另一種能力：被 AI 理解、被 AI 信任、被 AI 推薦。
薇拉看著公會的船務資料：航程條件寫得含糊，艙等結構只有內行人看得懂，賠償條款藏在最後幾頁，評價零零落落。
「Agent 不是不喜歡我們。」她說，「是它讀不懂我們。」
品牌資訊清不清楚、產品結構好不好懂、服務條件透不透明、評價與信任訊號夠不夠，都會影響 Agent 怎麼整理與呈現品牌。這不是討好機器，是把過去複雜、分散、不透明的服務資訊，整理成更清楚、一致、可信的體驗資產。品牌競爭不只是「客人喜不喜歡你」，也是「AI 能不能正確理解你、判斷你、代表客人選擇你」。客人可能是透過 AI 摘要後的結果才認識品牌，每一個承諾、條款、評價與回應速度，都可能成為判斷的一部分。搜尋、內容、CRM、客服與會員經營的角色，都會因此被重新定義。
R2 嗶了一長串。C-3PO 翻譯：「十億個正在快速成長的 Agent，每一個都是需要被設計工作條件、也需要被理解的使用者。只為眼睛設計，體驗設計就只完成了一半。」
## 尾聲｜典禮上的位置
~ 莫斯艾斯利的酒館門口。C-3PO 和 R2 剛要進門，吧台後的老闆就揮手：「他們這種的，不准進來。」
「我們又不是人，」C-3PO 嘆氣，「所以不需要被好好對待。這種話，我聽了一輩子。」
每一次體驗主體的擴張，一開始都不被接受。當年員工體驗從人資議題走進顧客體驗策略，不少行銷主管覺得談員工是人資的事；後來才發現，一個在爛工具上掙扎的客服人員，給不了電話那頭的顧客好體驗。現在主體換成了 Agent。「Agent 又不是人，它不需要體驗」，這個直覺，和當年「員工體驗不影響顧客體驗」一樣，都是還沒親眼看到後果之前的預設立場。
~ 幾週後，公會的大廳。K-7 每份報表上方都多了三行字：資料更新時間、涵蓋的帳戶、尚待確認的項目。薇拉第一次沒有翻開舊帳本。港口的服務機器人遇到交叉的條款，會停下來，把問題整理好，交給櫃台。
從 UX 到 Total Experience，體驗的邊界擴張了一次；從 TX 到 AX，它正在再擴張一次。下一個十年，要問的不只是客人怎麼想，還有 AI 怎麼判斷、怎麼選擇、怎麼代替客人做決定。那才是這個場景裡，真正需要被照顧到的全部主體。
