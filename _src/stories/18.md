TITLE: 星際大戰：第二位乘客
STYLE: 《星際大戰》續集式外傳 · 字卡開場的太空冒險，囉嗦的禮儀機器人與只會嗶嗶叫的搭檔
NOTE: 本篇為《星際大戰》（1977）的同人外傳式改編，沿用原片機器人 C-3PO 與 R2-D2 的角色設定。理財顧問 Wendy 為原文中的情境人物；電商退換貨 AI 客服 Agent 的導入經驗，為原文作者團隊親身見證，非角色經歷。
## 前情提要
> 本篇為外傳，時間線在原三部曲之後：一艘運輸艦在一次超空間跳躍中出錯，把 C-3PO 與 R2-D2 暫時寄放在 2026 年的地球。這兩台機器人，一台精通禮儀與翻譯，一台只會嗶嗶叫——剛好是人與 AI 之間最需要的兩種角色。
## 字卡｜序章
> 很久以前，在一個遙遠的星系……
> 又或者，就在 2026 年的地球。
> 二十年來，體驗設計的星圖上只畫著一種旅人：人類。如今，一種新的乘客登上了艦橋。它沒有眼睛，沒有情緒，卻握有決策的權力。
> 而大多數的艦隊，還沒有為它準備好座位。
## 篇章 I｜深夜裡的核對
~ 晚上八點，地球。一間財富管理辦公室，燈只剩一半還亮著。一台金色的禮儀機器人和一台矮矮的藍白搭檔，被一艘迷路的運輸艦臨時寄放在這裡。
「R2，安靜一點，」C-3PO 壓低聲音，「人類在工作。」
理財顧問 Wendy 盯著螢幕，游標停在「重新產生摘要」的按鈕上。這是她今天第四次，把 AI Agent 剛吐出來的客戶資產配置報告，重新拉開 Excel，手動核對一遍。
這套 Agent 的技術能力不差，幾秒內就能彙整客戶的股票、基金、保單配置，理論上能省下 Wendy 大半天。但上線三個月，使用率遠低於預期。顧問們寧可自己查，也不敢直接把 Agent 的輸出拿去見客戶。
R2-D2 對著那個 Agent 嗶嗶叫了幾聲。C-3PO 翻譯：「R2 說，那個 Agent 每次做事，都不告訴人它在做什麼——有沒有存取到最新資料？有沒有漏掉某個帳戶？現在看到的是不是舊版本？」他頓了一下，「說真的，R2，你自己也常常這樣。」
R2 發出一聲很不服氣的口哨。
它像一個悶著頭做事、從不回報進度的新人。動作再快，也沒有人敢把重要的事交給它。問題不在運算能力，而在它從來沒有被設計成「一個值得被信任的工作對象」。
> 這就是 Agent Experience，AX。
它牽動的不只是 Wendy 這樣的內部員工，還有每一個正在把決策交給 AI 的顧客。
## 篇章 II｜只有一種旅人的星圖
~ C-3PO 調出地球的體驗設計檔案。「天哪，」他說，「二十年來，他們的會議都長得一模一樣。」
行銷主管打開報告：App 的流失漏斗、官網熱圖、會員旅程的掉落點。焦點永遠是那個拿著手機、坐在電腦前的消費者。他是 UX 話語體系裡唯一的主角。從 1990 年代 Donald Norman 在蘋果確立概念，到 Nielsen Norman Group 系統化成方法論，這門學科從沒被正面質疑：體驗的主體是誰？答案只有一個：真實的人類消費者。
這個前提正在鬆動。Gartner 在 2022 年提出 Total Experience（TX）框架，第一次系統性擴展「體驗主體」：顧客體驗（CX）、使用者體驗（UX）、員工體驗（EX）不是三條平行航道，而是互相牽連的生態系。員工能不能快速拿到正確資訊，直接決定顧客在電話那頭的服務品質。Gartner 預測，到 2026 年，全球六成大型企業將仰賴 TX 策略轉型商業模式；Forrester 研究則指出，高品質員工體驗的企業，年均股票回報比同業高出 2.3% 到 3.8%。
NUM: 2.3–3.8%｜高品質員工體驗企業，年均股票回報高於同業的幅度
在 TX 時代，體驗同時涉及消費者的 UX、員工的 EX，以及高階主管的決策體驗（Decision Experience）。但三者加起來，仍然只有一種主體：人類。
「直到我們這種東西出現。」C-3PO 說。
## 篇章 III｜新乘客
2025 年 1 月，雲端託管大廠 Netlify 的執行長 Mathias Biilmann 提出一個概念：我們已經有 UX 讓使用者有好體驗，有 DX（Developer Experience）讓開發者有清楚文件；當 AI Agent 成為使用產品的主體之一，就需要第三個概念——讓 Agent 在互動時，也有順暢、可預測、可信賴的體驗。
麥肯錫 2025 年報告畫出了輪廓：88% 的受訪企業已在至少一項商業功能中定期使用 AI，但只有約三分之一開始規模化。一扇奠定未來十年標準的窗口正在打開；企業現在做的設計決策，將決定日後的基準線——不管是內部的工作 Agent，還是顧客面對的服務 Agent。
## 篇章 IV｜被壓縮的航程
~ R2 投射出一張全息航線圖。過去的航線又長又彎，新的航線只剩短短一截。
過去二十年，顧客體驗建立在「人主動操作」上：有需求就搜尋，看到廣告就點擊，有問題就問客服。系統在顧客發出明確訊號之後才回應——指令回應式體驗（Request-Based Experience）。AI Agent 把它推向代理協作式體驗（Agent-Assisted Experience）：理解目標、判斷情境、整理選項，在授權範圍內協助完成任務。所以 Agent 不是「更聰明的 Chatbot」；Chatbot 解決回答的效率，Agent 改變任務本身怎麼被執行。
買旅遊產品，過去要一一比較航班、飯店、評論、保險，再付款排行程。在 Agent Experience 裡，顧客說出預算、日期和偏好，Agent 就先整理出幾套可執行方案，搜尋與比較成本被 AI 吸收。
> 這叫做顧客旅程壓縮（Journey Compression）。
接觸點變少，不代表品牌影響力不重要；每一次被 Agent 選中、推薦、呈現的機會都更關鍵。Agent 可能只給三個選項而不是三十個，品牌怎麼被理解、排序、信任，就是新戰場。介面也在變：過去固定，現在因人、因情境、因任務而變——同一個金融服務，對新客戶呈現簡化的方案比較，對既有會員直接顯示資產狀況和到期提醒。這是生成式使用者介面（Generative UI）的商業意義：介面從固定流程，變成動態的服務入口。
企業理解顧客的方式也在變。除了顧客主動表達的意圖，AI 能讀出還沒說出口的訊號：反覆查看某類商品、購買週期接近、在流程中停留過久。競爭從需求捕捉（Demand Capture）轉向需求預測（Demand Anticipation）。但同一種能力，可以用來更早打擾顧客，也可以讓 Agent 懂得節制：知道何時提醒、何時協助、何時沉默。傳統自動化追求觸發與轉換；Agent Experience 必須同時理解情境、任務、風險和人的感受。
## 篇章 V｜沒有按鈕可看的乘客
~ C-3PO 試著用人類的方式和那個 Agent 溝通：鞠躬、放慢語速、把畫面調得更好看。毫無反應。「我有不好的預感。」他說。
理解 AX 不難，難的是轉換一整套直覺。UX 的訓練核心是同理心，感受使用者的情緒和挫折；這對設計 AX 幾乎沒有直接用途。Agent 沒有情緒，不會因為頁面好看多停留；但它會因為 API 回應不穩定而中斷任務，會因為指令不夠明確，在幾十個步驟後偏離初衷。
Nielsen Norman Group 2026 年的 State of UX 報告說得直接：2026 年，信任將是 AI 體驗最核心的設計問題；越來越多 Agent 在還沒準備好時被推出，挑戰只會加劇。
信任有兩層。設計層，AI 新創公司 Pixelmojo 歸納出六個 AX 信任模式：
> 意圖預覽 · 自主性調節 · 信心訊號 · 可解釋推理 · 行動稽核 · 升級路徑
治理層，企業要先回答三個問題：AI 知道我什麼？AI 可以替我做什麼？AI 做錯了誰負責？低風險任務可以高度自動化，例如查訂單、排提醒；高風險任務需要明確確認與人工支援，例如金融交易、醫療建議、保險申請。最成功的品牌，是最能讓顧客放心授權的品牌：顧客不授權，功能再多的 Agent 也動不了。
> 信任，是 Agent Experience 能不能運作的基礎設施。
## 篇章 VI｜知道何時停下的機器人
~ R2 播放一段從前線傳回的影像，署名：原文作者團隊。
「升級路徑」的重量，作者團隊在一個電商客戶的 AI 客服 Agent 導入過程中親身見證過。那個處理退換貨的 Agent，初版沒有清楚的升級路徑。一位顧客同時遇上三個問題：商品瑕疵、超過鑑賞期兩天、跨境退貨的物流特例。Agent 沒停下來，先引用一般政策，發現不適用又改口引用瑕疵品條款，兩次回覆前後矛盾。顧客打出：「所以到底可以退還是不可以」。
後來團隊加了門檻：案例涉及兩項以上政策交叉判斷，Agent 就主動停下，回覆「這個問題我想讓同仁協助您確認」，把三個衝突點整理成摘要即時轉接。改版後，這類案例的滿意度不再斷崖式下滑；客服團隊也開始主動查看 Agent 轉來的案例，而不是從頭再問一次。
「你看，」C-3PO 對 R2 說，「知道自己什麼時候該閉嘴、找人類幫忙，是一種美德。」
> Agent 的限制是設計出來的，不是缺陷。不知道自己邊界在哪裡的 Agent，比清楚知道何時該停下的 Agent，危險得多。
## 篇章 VII｜舊酒新瓶？
~ 一位老顧問嗤之以鼻：「這些東西，三十年前不就寫過了？」
這值得誠實面對：意圖預覽、可解釋推理，很像可用性工程裡「系統狀態可見性」的變體，Jakob Nielsen 在 1990 年代就寫過類似守則。但 Wendy 和退換貨顧客的案例指出差異：UX 的失敗，發生在「人看不懂畫面」；AX 的失敗，發生在「另一套系統沒有能力表達自己的狀態」。Agent 不是看不懂按鈕，它根本沒有按鈕可看。互動的一方換成沒有視覺、沒有情緒卻有決策權的軟體，好看、直覺、令人愉悅這些詞幾乎失效，得換成穩定性、可驗證性、可追溯性。不是換皮，是換了整套評分表。標準未定，正是這個階段最真實的樣子；也因此，現在的設計決策會決定日後的基準線。
## 篇章 VIII｜四道星門
第一道：從設計介面，到設計工作條件。對 Agent 而言介面幾乎不存在，它的工作條件是另一套語言：指令的精確度、資料存取的邊界、出錯時的回饋機制。麥肯錫指出，Agentic AI 早期成功案例的共同點，不是挑了最聰明的模型，而是挑了最清晰的工作流程。
第二道：從單一使用者，到多主體協同——不只多個 Agent 之間，也在顧客端和員工端之間，兩者是同一件事的兩面。員工得在多個系統間查資料、複製貼上、確認狀態，顧客就感受不到即時一致的服務；內部 Agent 能幫員工快速理解顧客背景，外部體驗才順。AX 不是前台多一個 AI 入口，而是企業作業系統的治理問題：前台 Agent 再聰明，後台資料分散、流程斷裂、員工接不了手，顧客感受到的仍是不連貫。
第三道：從單次會話，到持續關係。Agent 記住今天學到的，明天更有用；設計師要思考記憶架構：記什麼、記多久、何時記憶反而帶來偏誤而需要重置。
第四道：從以人為中心，到以信任為中心。「以使用者為中心」沒有過期，但使用者不再只是人。對人，信任靠一致的視覺語言；對 Agent，信任靠穩定的 API 回應和可驗證的資料格式。世界經濟論壇 2026 年的分析指出：要讓人信任一套 AI 的作為，得先讓人看懂它知道什麼、被允許做什麼、實際做了什麼。這是 UX 的終極目標，也是 AX 的起點。
## 篇章 IX｜被選中的那一艘
~ 星港停著三十艘船。顧客的 Agent 只帶他看三艘。C-3PO 揮揮手：「這些不是你要找的船。」然後指向第四艘。
過去品牌爭的是注意力；未來還需要被 AI 理解、信任、推薦。顧客透過 Agent 比較時，品牌資訊清不清楚、產品結構好不好懂、服務條件透不透明、評價與信任訊號夠不夠，都影響 Agent 怎麼呈現品牌。這不是討好機器，而是把複雜、分散、不透明的服務資訊，整理成清楚、一致、可信的體驗資產。品牌競爭不只是「顧客喜不喜歡你」，也是「AI 能不能正確理解你、判斷你、代表顧客選擇你」。顧客可能透過 AI 摘要認識品牌，每一個承諾、條款、評價和回應速度都可能成為判斷的一部分。十億個快速成長的 Agent，每一個都是需要被設計工作條件、也需要被理解的使用者。只為人眼設計，體驗設計就只完成了一半。
## 終章｜兩個座位
~ 幾週後。Wendy 的 Agent 會在每份報告上方標示：資料更新時間、涵蓋的帳戶、尚待確認的項目。Wendy 第一次沒有打開 Excel。R2 得意地轉了一圈。
每一次體驗主體的擴張，一開始都不被接受。當年 EX 走進 CX 策略時，不少行銷主管認為談員工是人資的事；後來才發現，在爛工具上掙扎的客服，給不出好體驗。現在主體換成了 Agent。「Agent 又不是人，不需要體驗」——這和當年「員工體驗不影響顧客體驗」一樣，是還沒看到後果前的預設立場。
從 UX 到 TX，邊界擴張了一次；從 TX 到 AX，它正在再擴張一次。下一個十年，企業要問的不只是顧客怎麼想，還有 AI 怎麼判斷、怎麼選擇、怎麼代替顧客做決定。這才是需要被照顧到的全部主體。
運輸艦終於回來接他們。C-3PO 在門口回頭，對 Wendy 微微欠身：「願原力與你同在。」
